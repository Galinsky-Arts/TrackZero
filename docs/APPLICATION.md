# TrackZero application: run, operate and deploy

TrackZero is now one runnable Node 24 application (`bin/trackzero.mjs`) that composes every existing
handler on a single origin, serves a web UI, and provides a first-party account service. The handlers'
own security logic is unchanged; `src/platform/` only wires identity, durable stores and routing.

## What runs where

| Path | Purpose |
| --- | --- |
| `/` (`public/`) | Web UI: account, creator studio, rights review, listener features, discovery, operator console (hash routes `#/…`) |
| `/stations/:id`, `/albums/:id` | Server-rendered guest station and album pages (existing `guest-radio.mjs`) plus shared stylesheet |
| `/api/auth/*` | Better Auth 1.7.18 (sign-up, sign-in, sign-out, HttpOnly session cookie) on PostgreSQL |
| `/api/account/token`, `/api/account/session` | Same-origin exchange of the account session for a 10-minute opaque access token (kept in browser memory only) |
| `/oauth2/introspect` | RFC 7662 introspection with confidential-client Basic authentication |
| `/v1/me`, `/v1/onboarding` | TZ-02 onboarding (listener; artist/label by single-use invitation) |
| `/v1/stations…` | TZ-03/04 storefront publication (operator-verified station claim; offers need approved sale rights) |
| `/v1/rights/…` | TZ-05 rights claims, reviews (separate `rights_reviewer`), withdrawals, decisions |
| `/v1/programs/:station` | TZ-06 program sequence (owner only; songs need approved broadcast rights) |
| `/v1/interstitials…`, `/v1/sponsor-campaigns…` | TZ-07/08 drafts and campaigns (publication/approval need verified encrypted media) |
| `/v1/station-engine/events`, `/v1/stations/:id/status` | TZ-09 engine reports (operator-issued engine credential) and owner status |
| `/v1/discover` | TZ-21 shareable discovery page (HTTPS origin) |
| `/v1/album-checkouts`, `/v1/support/…`, `/v1/grooves/…`, `/v1/reports/…`, `/v1/point-redemptions`, `/v1/library`, `/v1/privacy`, `/v1/complaints` | Endpoint-encrypted features: answer `503 ENDPOINT_ENROLLMENT_REQUIRED` until approved endpoint codecs are composed. No plaintext fallback. |
| `/operator/v1/…` | Operator provisioning (invitations, station claims, role grants, engine credentials), Bearer `TZ_OPERATOR_TOKEN` |
| `/healthz`, `/readyz` | Liveness; honest readiness with storage durability, feature states and payment configuration |

Identity: resource handlers authenticate every request with the existing `createIntrospectionAuthenticator`.
In `TZ_IDENTITY=builtin` mode the introspection call goes in-process to the account service using the same
RFC 7662 contract and client credentials; `TZ_IDENTITY=external` points it at any external IdP. Provider data
never grants roles: roles come from onboarding invitations, operator grants (`rights_reviewer`, `sponsor`,
`moderator`) and verified station-claim ownership (`broadcaster`).

## Local run

```sh
source ~/.node24env            # Node 24.19.x
npm run deps:prepare            # fetch, verify, build and pack pinned DAE/DRE (dependency-pins.json)
npm ci --ignore-scripts
cp .env.example .env            # fill DATABASE_URL, TZ_DATA_DIR and fresh random secrets (>=32 chars)
npm run db:migrate
npm start                       # http://localhost:3000
```

HTTP is accepted only for loopback origins; any other origin must be HTTPS. Remote PostgreSQL must use
`sslmode=require` (certificate-verified). Provision the first creator with `npm run operator -- invitation artist`
or the operator console, then `station-claim <station-id> <account-reference>` after verifying ownership
out of band.

## Tests

`npm test` runs every node:test suite against the pinned engines (153 tests at this revision). Set
`TZ_TEST_DATABASE_URL` to a **disposable** PostgreSQL database (its `public` schema is dropped) to run the
Better Auth/introspection and Chromium journey suites; set `CHROMIUM_PATH` if the playwright-core browser
is not installed. CI runs the full suite with a PostgreSQL service and fails if it would skip.

## Free preview deployment (render.yaml)

Live development preview: https://trackzero.onrender.com (auto-deploy off; deploy manually after merging).
The operator token is a Render secret environment variable (`TZ_OPERATOR_TOKEN`); read it from the Render dashboard.

`render.yaml` describes a $0 preview: Render free web service (virginia, Node 24.19.0, auto-deploy off)
with accounts in a Neon free PostgreSQL project (`trackzero`, aws-us-east-1, created in the Galinsky Labs
Neon organization). Secrets are generated by Render; `DATABASE_URL` and Stripe values are set outside source.

**Storage warning.** Free Render has no persistent disk. Accounts persist in Neon, but stations, rights,
programs, grants and engine credentials live in SQLite under `TZ_DATA_DIR` and are lost on every restart,
spin-down or deploy. The UI banner and `/readyz` say so. Production requires a persistent disk (a paid
owner decision), `TZ_STORAGE_DURABILITY=persistent`, backups and a restore drill.

## Payments

Set `STRIPE_SECRET_KEY` (sk_test_…), `STRIPE_WEBHOOK_SECRET` (whsec_…) and `STRIPE_ACCOUNT_ID` (acct_…).
When any is missing the UI shows "Payments not configured". When set, the server verifies them with DRE's
read-only sandbox account probe and reports `sandbox_verified` in `/readyz`; values are never echoed. Album
checkout itself still requires an enrolled endpoint (its request and receipt are endpoint-encrypted), so
webhook settlement is composed together with that endpoint integration, not before it.
