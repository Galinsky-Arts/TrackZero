# TZ-02 onboarding implementation status

The draft branch provides a local SQLite account store, one-time random 256-bit invitations whose hashes alone are stored, a fail-closed opaque-token introspection adapter, an HTTP handler, a bounded Node HTTP server and a configured application entry point. Listener enrollment is self-service; artist and label role grants need a tenant/application/role-scoped invitation provisioned outside the public API. The server derives subject and tenant only from a trusted introspection response. Provider roles are ignored, and account roles alone confer no station or device decrypting authority.

`node --test tests/*.test.mjs` on Node 24 exercises normal enrollment, duplicate replay, persisted restart recovery, cross-tenant/application/subject isolation, invitation denial and expiry, provider failure, HTTP origin and body limits, and an interrupted transaction rollback. See [TZ-02-RUNBOOK.md](TZ-02-RUNBOOK.md) for runtime configuration and operational assumptions.

Planning CI now runs the registry contract tests and the complete onboarding product suite on each pull-request head. Local and hosted tests validate the software boundary only. No identity-provider credentials, deployed persistent volume, or production validation are available in this assignment. DRE-02 is merged upstream, but a future station grant must still be explicit and independently verified before an account can acquire engine permissions. These external deployment and integration gates prevent production-login or release claims; they do not invalidate the tested local onboarding implementation. No hardware, field or E2EESA evidence is claimed.
