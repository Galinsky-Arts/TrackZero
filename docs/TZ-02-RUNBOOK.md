# TZ-02 onboarding runtime and validation

The server exposes `POST /v1/onboarding` and `GET /v1/me` through `bin/onboarding.mjs` on Node 24. The process requires `PORT`, an absolute `TZ_DATABASE_PATH` on an operator-provisioned persistent volume, `TZ_PUBLIC_ORIGIN` (HTTPS), `TZ_INTROSPECTION_ENDPOINT` (HTTPS), `TZ_ISSUER`, `TZ_AUDIENCE`, `TZ_APPLICATION`, and confidential `TZ_CLIENT_ID` and `TZ_CLIENT_SECRET`. The identity provider and volume are not provisioned by this repository. Start with `node bin/onboarding.mjs` after configuring those values through the deployment's secret mechanism; do not place the client secret in the repository or a command line argument. TLS must terminate at a trusted proxy, and its public origin must exactly match `TZ_PUBLIC_ORIGIN`. The server ignores client Host and forwarded headers for the origin decision.

The confidential backend POSTs each opaque bearer token to the configured introspection endpoint with a five-second timeout. Only active responses with the exact issuer, audience, future expiry, valid subject and tenant become a local principal; provider roles are ignored. An unreachable provider fails closed with 503. Production should use an introspection provider that returns these claims to the registered confidential client and protects its token endpoint. There is no development identity fallback.

An operator provisions an artist or label invitation through the non-HTTP `OnboardingStore.provisionInvitation` method. It returns a random, 256-bit token once; the database stores only its SHA-256 digest. The invite is scoped to tenant, application and role, expires, and is consumed atomically on first grant. Deliver it through an operator-approved private channel. No public endpoint creates invitations. Listener enrollment needs no invitation. The returned account is scoped to the verified provider subject, tenant and application; an account role grants no station or device decrypting authority on its own.

Run `node --test tests/*.test.mjs` on Node 24. The local suite covers enrollment, persistent restart recovery, cross-tenant and cross-role denial, invitation replay/expiry, interrupted transaction rollback, provider authentication failures, and an actual Node HTTP boundary including body limits. The repository's existing planning workflow does not run this product suite. Protected CI configuration and actual deployed provider/volume validation remain separate gates. Verify the DRE-02 contract and an explicit station membership grant before mapping these account roles to engine permissions. No production, hardware, field or release evidence is claimed by these tests.
